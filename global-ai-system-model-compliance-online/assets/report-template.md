# 三层AI综合合规评估报告模板

本模板用于将问卷事实渲染成面向业务的报告。方括号内容由agent替换；不要把内部判断编号或推理过程放入正文。

对话交付时，必须在消息正文直接写出主要风险、建议和待办、以及不处理时的最严重可能后果；全量版还必须写出上线状态。Markdown和JSON文件只是审计附件；不得只回复“报告已生成”、文件路径或链接。法律依据放在业务结论之后集中列示。

## 输出模式分支（只选择一个）

报告必须读取问卷中锁定的 `P0` 模式；不得把轻量版结果套进全量版结论段，也不得在同一交付物中同时输出两套相互冲突的状态。

### 轻量版初步评估

轻量版的业务正文只使用标题“初步风险提示”，并按以下顺序输出：

1. 已知事实和来源；
2. 已发现的风险线索（使用条件式语言，不作最终法律定性）；
3. 待内部核实的事实和所需材料；
4. 尚未覆盖的主题，以及每个主题不评估可能造成的最严重后果；
5. 建议何时升级全量版、升级前先准备什么。

轻量版不得输出“总体状态”“总体风险”“上线状态”“可上线”“合规”或其他完整审计结论，也不得把“未发现线索”写成低风险或已满足义务。轻量版的自然语言结论应明确说明：这只是业务事实初筛，不能据此决定投放、继续运行或停止整改。结构化附件可以记录 `not_assessed` 和待核字段，但不能用全量版 `conclusion` 字段替代上述初步提示。

轻量版业务正文骨架：

```text
# 初步风险提示
项目：[项目代号/产品名称]
评估日期：[日期]；事实截止日：[日期]；法律资料核验日：[日期]

已知事实：[用业务语言列出事实和来源]
已发现风险线索：[说明触发线索、条件和需要补证的地方]
待内部核实：[逐项写责任职能、材料、复核日期和暂时控制]
尚未覆盖及最严重后果：[逐项列出未展开主题及不评估的最严重可能后果]
升级建议：[说明升级全量版的触发条件和准备材料]
```

### 全量版评估

只有全量版才使用本模板后面的“一页结论”以及“总体状态、总体风险、上线状态”字段。全量版仍须在对话正文用自然语言先给业务结论，再附结构化文件和集中法律依据；关键事实未核实时不得给无条件“合规”或“可上线”。

## 资料过量时的首屏

如果材料尚未全部读取，或出现相互矛盾，先输出短版首屏，不要直接渲染完整报告。首屏固定包含：已确认事实、冲突和待核事实、暂定层级路径及条件式红线、本轮不超过8个最关键问题和对应自测表、已读和待读材料清单。冲突解决前总体状态只能是“暂不能确认”或“有条件上线”；完整法律依据、建议和待办按层级分批追加。

## 评估导向与层级

本次评估默认从中国大陆业务团队的使用场景出发，第一层并行检查中国大陆、欧盟和美国加州的AI透明度。欧盟AI Act系统层（禁止性实践、Annex I/Annex III高风险）和模型层（GPAI及系统性风险）属于第二层核心；GDPR、CCPA/CPRA、AI平台跨境数据流和美国敏感数据限制属于附属筛查，只围绕本平台的输入、输出、日志、备份、远程运维和供应商链路展开。未选择的层级不等于不适用，报告应当写明“未评估”和可能的最严重后果。

先看“给业务的结论”和“阻断事项”，再看各层的法定义务和建议措施。法律依据集中放在“法律依据与效力标签”和“法律原文摘录”中；建议措施、技术方案和风险判断不得伪装成法条。每项未来义务同时列出已经落入定义的状态、法定生效或适用日期、到期前准备动作和复核日期。
