# 三层AI合规业务问卷

本文件是 agent 的提问底稿。直接填写人是企业内部业务、产品、技术或法务，不是被评估产品的消费者。发送给填写人时，只发送当前小组的白话问题和业务可见自测表，不发送内部判定列、法规编号、R1 至 R4 或后台层级编号。后台仍固定建立三层记录；业务入口只决定先问什么和问多深，不能直接得出“不适用”或“合规”。

## 给业务人员的开场白

本问卷由内部业务、产品、技术或法务填写；问题中提到的消费者、客户、员工等，均指被评估产品的实际或预期使用者。

这不是法律考试。请按产品现在真实运行或计划上线的情况回答；不知道就选“不确定”，不要猜。题目只问产品、使用者、数据、控制措施和现有材料，法律判断由系统在后台完成。

这项评估先看三个地区的AI透明度，也就是使用者是否需要知道自己在和AI互动、内容是否由AI生成、内容怎样标识和验证。若产品涉及欧盟，还可以继续看产品用途是否受限制、是否可能影响重要决定，以及使用的模型来自哪里、由谁对外提供。个人信息、跨境传输、版权、消费者保护、产品责任和Cookie等事项只围绕本AI平台的真实运行做附属筛查。

明确回答不知道、没有文件、只有口头说法或证据调不出来时，答案仍算已提交并进入待内部核实，不会被改写成“否”或“已经合规”，也不会重复询问。材料互相矛盾时只把冲突字段列为需要更正；空白才算尚未提交。

## 后台事实记录清单（不发送给业务）

每一条业务回答都由 agent 在后台附上一张事实记录卡。记录卡不是让填写人选择法律身份，而是防止把品牌、客户名称或接口名称误当成实际角色。至少保存以下内容：填写人身份；产品实际运营方；产品最终用户；模型开发方或控制方；技术供应商或合作方；涉及法域；事实对应的时间或版本；事实来源；确定程度。确定程度只可写“已确认”“业务陈述”“不确定”或“存在冲突”。

如果一条事实涉及多个实体或目的，分别建记录，不能把本公司、客户、上游模型方、云服务商和合作品牌合并成一个角色。产品运营方、模型开发或控制方、技术供应商、合作品牌方和最终用户必须分别核对；agent 不从产品名称、客户名称、品牌或接口名称推断谁部署、谁修改或谁承担法律角色。关键事实确认后，再补证据名称、日期和存放位置；证据缺失只记为待确认。

每次发送下一组前，agent 检查已答题、冲突、未经确认的假设和不适用角色。若有冲突，先逐条回显冲突并要求更正；若只是部分回答，只补未答或冲突行。

## 第一轮：P0评估模式

第一轮只发送这一题，不得同时发送地区或产品问题。

问题：这次希望用哪种评估方式？

选项，单选：

- 轻量版初步评估
- 全量版评估
- 不确定，先按轻量版初步评估

说明：轻量版用日常能看到的产品事实快速找风险，不作完整上线结论。全量版按范围分组检查透明度、产品用途、模型、数据和证据。选择第三项后按轻量版继续，模式题视为已提交且不会重复询问。

题后立即附只含`P0`一行的业务自测表，最后一列写清三种选项的区别。可用`python3 scripts/render_business_table.py --keys P0 --output /tmp/business-mode.md`生成。

## 第二轮：P1至P4范围入口

模式提交后，一次发送以下四个简短问题。`P2`和`P3`只选择评估范围，不延伸技术事实。四题后立即附只含`P1`至`P4`的业务自测表。

### P1 地区

问题：本次咨询要看哪些地区？

选项，可多选：

- 中国大陆
- 美国
- 欧盟
- 尚未确定

说明：只按产品实际或计划提供的地区选择。选美国时先看加州透明度；更广泛的美国附属筛查由后续范围决定。

### P2 咨询重点

问题：这次先想了解哪一类问题？

选项，单选：

- 只看AI内容透明度
- 透明度加欧盟产品或系统的使用方式
- 透明度加模型来源和使用方式
- 透明度、系统和模型都看
- 不确定

说明：产品或系统使用方式是产品做什么、影响谁；模型来源是能力来自谁、由谁控制。这里不要求判断高风险或模型法律类别。

### P3 附属筛查范围

问题：透明度之外，是否顺便提示这个AI平台可能涉及的其他事项？

第二步只选透明度时显示：

- 只做透明度
- 暂不做附属筛查
- 透明度之外顺便提示个人信息、跨境、版权等附属事项
- 不确定

第二步还选择系统或模型时显示：

- 只做已选核心范围，不做附属筛查
- 还看欧盟产品、系统或模型使用，并顺便做附属筛查
- 还看欧盟产品、系统或模型使用，但附属筛查不确定
- 不确定

说明：附属筛查只围绕本AI平台的输入、输出、日志、备份、远程访问和供应商，不扩展为企业一般性数据审计。

### P4 产品和使用者

问题：请用一句话说清产品是什么、给谁用。

填写选项：

- 产品一句话，加主要客户或使用者
- 最终使用者不清楚，写产品一句话并把使用者填“不确定”

例子：面向欧洲企业客户的中文智能客服助手；最终使用者由客户决定，目前不确定。

回显时区分内部填写人和被评估产品的使用者，不从“面向消费者”等字样自行增加地区、运营方或模型权限事实。可回显为：“被评估产品的最终用户为消费者”；不能写成“本问卷使用者是消费者”。

## 路线、进度和不确定项

`P0`显示模式选择1题的进度。随后入口显示4步：已确认、已提交待内部核实、尚未提交和需要更正。明确“不确定”属于有效提交，进入`pending_verification`，不计入还需提交，不得再次询问。只有空白、未知答案或互斥冲突才计入待补或待更正。

入口和后台`R1`至`R4`登记有效后锁定路线，并显示：

“本次共需完成 X 组问卷；当前第 Y 组；已完成 Z 组；还剩 N 组问卷。本轮待答 M 题。”

轻量版固定2组、每组5题，整条路线固定10题：

- `LT1`：`P5`、`B1`、`B2`、`B3`、`C1`，共5题
- `LT2`：`C2`、`C3`、`D0`、`E0`、`F0`，共5题
- `C2`和`C3`先看内容外观、页面提示和来源信息；`D0`、`E0`、`F0`分别用白话快速筛查欧盟系统线索、模型线索和本AI平台附属数据线索。轻量版即使入口只选择透明度，也会完成这三项快速筛查；`P2`和`P3`只决定全量版是否发送后续详细组，不改变轻量版题数。
- 地区范围先由入口`P1`和展示位置`P5`作初步记录；三地实际可达和展示路径的逐项核验留在全量透明度题`C4`，避免轻量版重复提问。

全量版按范围为3至7组：透明度核心`T1`至`T3`，系统层`T4`、模型层`T5`、附属筛查`T6`和`T7`按范围加入。每轮2至8题，只有补一个空白或纠正一个冲突时才发1题。

路线锁定时保存`route_signature`、`locked_total_groups`和`enabled_group_ids`。后续范围变化先回显旧路线和候选路线，候选总数不计入当前进度。已提交或已更正的题不再发送。

## P6全量版资料能力门控

全量版业务主线完成后，在任何技术、数据或合同明细前发送`P6`。轻量版不发送本题。

问题：你现在能否查看或协调核对技术、数据或合同资料？

选项，单选：

- 可以，我能查看或协调核对这些资料
- 目前只能回答产品页面和业务流程
- 不确定，先只按业务事实评估

只有第一项展开`technical_detail_keys`。后两项都视为有效提交：继续业务主线，把接口、服务器、文件格式、签名、密钥、远程访问、模型版本和合同事实一次列入补证清单，不重复询问`P6`。

业务人员不需要判断任何法律身份或法律缩写。只描述谁决定用途、谁按指令操作、谁再委托服务商和数据去了哪里；这些事实由 Skill 在后台映射。确需提及时先解释白话含义；模型权重说明为“可下载和修改的模型参数文件”，RAG说明为“从资料库取片段再生成回答”，GPC说明为“浏览器发出的通用退出信号”。

## 小组发送规则

每个问题的所有选项都分别使用一行以`-`开头的普通列表。每组问题后立即附当前组业务自测表，最后一列必须是“填写注释（给业务部门）”，逐行给选择方法、业务例子和建议材料。不得要求业务使用固定答句，不得收集个人姓名或联系方式。

业务可见自测表只能从`assets/business-self-check-table-public.md`或渲染器输出复制，不能将选项改写成分号串或省略换行。公开表使用“模式题”“第1步”至“第4步”“开始问题”或“第1题”（同一条消息保持一致）以及“资料深度问题”等标签，不显示`P0`至`P6`、`R1`至`R4`或路线键。发送前逐项检查表头含“填写注释（给业务部门）”、每个选项单独以`-`开头一行、没有星号或下划线；不满足时先重新渲染。入口`P1`至`P4`收齐后，除非业务要求暂停，应在同一回复锁定路线并发送第一组问题，且首行固定写“本次共需完成 X 组问卷；当前第 Y 组；已完成 Z 组；还剩 N 组问卷。本轮待答 M 题。”，不能只写“当前为第一组”或只写总题数。

用户只回答部分题时保留已提交答案，只补空白或冲突；明确“不确定”不再追问。每批答案先回显“已确认事实、待内部核实、需要更正”，再更新固定进度。

## 后台入口映射（不得发送给业务）

`P0`选择模式；`P1`映射地区；`P2`映射透明度、系统和模型范围；`P3`映射AI平台附属范围；`P4`建立产品和实际使用者事实；`P5`补展示位置；`P6`只控制全量版技术明细。收到入口后自动建立中国大陆、欧盟、美国加州透明度、欧盟系统、欧盟模型和AI平台数据流记录，并生成`R1`至`R4`，不得把这些内部键发送给业务。
