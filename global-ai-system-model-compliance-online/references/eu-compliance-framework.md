# 三层评估决策框架

本文件是内部判定规则。面向业务人员的文字只从问卷和自测表生成，不直接发送本文件。

## 一、机器可读状态

事实字段使用以下状态：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| confirmed | 业务给出明确回答并有证据 | 可作事实基础 |
| unknown | 空白、不确定或缺证据 | 不得当作否；条件式触发并按最严格路径预警 |
| conflicting | 回答彼此矛盾 | 暂停结论，列出矛盾并要求证据 |
| legal_debate | 事实明确、法律解释有争议 | 列争议和保守解释，不改写事实 |
| verified_negative | 有充分证据排除某触发条件 | 可记录不触发及证据 |

义务状态使用：

- triggered：已确认触发。
- conditional：若未确认事实成立则触发；必须同时列strict_assumption。
- not_triggered：已确认不触发且有排除证据。
- pending_date：主体和义务已落入，但适用日期尚未到；不能写成“完全不适用”。
- pending_verification：法律版本、成员国转置或效力未核验。

## 二、总路由

采集项目和数据流后，按以下四条并行路径处理：

1. Layer 1：CN/EU/CA透明度触发测试。
2. Layer 2A：EU AI Act范围→Art.5禁止→Art.6高风险→角色义务。
3. Layer 2B：GPAI定义→provider/下游provider→系统性风险→模型义务。
4. Layer 3：GDPR、CCPA/CPRA、美国敏感数据→跨境机制→PLD产品/责任→CDSM版权/TDM→ePrivacy终端设备。

任何一条红线都独立决定上线状态；层级之间采用并行适用，不是满足一层即可。

## 三、Layer 1透明度触发表

对每个法域逐项记录：目标市场/用户、内容模态、生成或合成方式、是否公开传播、自然人交互、谁以自己名义提供、平台规模、机器可读标记/显式披露、例外和证据。中国、欧盟和加州的法条、门槛和例外分开判断。

欧盟Art.50的法律义务和Transparency CoP/Art.50 Guidelines分栏。CoP、指南、标准统一效力标签为“欧盟建议的良好实践/解释性材料（非独立法定义务）”。

## 四、Layer 2A系统层决策树

### 1. 连接点

若满足以下任一项，继续AI Act评估：

1. 系统或模型在欧盟投放市场或投入使用。
2. provider在欧盟境外，但系统输出在欧盟使用，且该使用是有意安排、合同或营销可合理预见的。
3. 欧盟境内机构或自然人作为受影响者，或系统由欧盟deployer控制使用。

偶然、不可预见且未经授权的下游使用不能自动扩张provider义务，但仍应记录用途限制、监测和下游信息。

### 2. 不可接受风险

逐项核对现行Art.5文本和例外：操纵/欺骗、利用脆弱性、社会评分、预测性执法、无差别抓取人脸图像、违法生物识别分类、工作场所/教育场景情感识别、实时远程生物识别等。题目回答unknown或证据冲突时，写成：

status = conditional
strict_assumption = “若该能力或用途成立，则按Art.5禁止路径处理”
launch_blocker = true

禁止性实践一旦确认，结论为“暂缓上线”，并列停止、删除、改用途或寻求适用例外的动作。例外必须证明法定授权、目的、保障措施和范围。

### 3. 高风险路径

先检查Annex I安全组件/产品法规路径，再检查Annex III预期用途路径。Annex I使用联网脚本中的20项现行清单及下载的命中产品法规；历史Directive 2006/42/EC只作过渡参考。Annex III按现行合并文本和官方指南逐类核对。

Article 6(3)的非高风险例外需要逐项证明：用途不涉及法定高影响决定、输出不影响自然人、或满足条文规定的狭窄条件。通用工具的客户用途不能只凭合同免责声明排除。

### 4. 高风险义务矩阵

| 主题 | 主要AI Act锚点 | 证据例子 |
|---|---|---|
| 风险管理 | Art.9 | 风险识别、测试、残余风险和持续更新记录 |
| 数据治理 | Art.10 | 数据来源、代表性、偏差、质量和治理流程 |
| 技术文档 | Art.11 | Annex IV文档、版本和变更历史 |
| 自动记录 | Art.12 | 日志完整性、保存期限和访问控制 |
| 使用说明/信息 | Art.13 | 面向deployer的说明、限制和性能 |
| 人类监督 | Art.14 | 有权限且能改变结果的人员、培训和升级 |
| 准确性/稳健性/网络安全 | Art.15 | 指标、压力测试、漏洞和修复 |
| 质量管理 | Art.17 | QMS、责任、纠正和审计 |
| 合格评定/注册 | Art.43、48、49 | 评定文件、CE、EU数据库记录 |
| 上市后监测 | Art.72 | 监测计划、反馈、投诉和纠正 |
| 严重事件 | Art.73 | 识别、报告时限、主管机关沟通 |

将provider、deployer、进口商、分销商、授权代表、下游provider分列；不得将一方义务笼统转给另一方。

## 五、Layer 2B GPAI决策树

1. 记录模型是否具有显著通用性、多任务能力、可集成性，以及是否仍处于投放前研究/原型阶段。
2. 记录谁开发或委托开发、谁控制权重、谁决定训练/微调、谁以自己名义投放或投入使用、采用API还是权重下载。
3. 若下游修改可能显著改变通用性、能力或系统性风险，按“可能成为新provider”路径核验。训练算力超过原模型三分之一是官方指南的指标性参考，不是自动法律门槛。
4. 系统性风险评估要同时看高影响能力、欧盟市场影响、可规模化传播、法定/指南计算量指标和委员会指定。未知项不得按低风险处理。
5. 输出模型义务：技术文档、下游信息、版权政策、训练内容摘要、代表和事件合作；系统性风险模型再加评估、对抗测试、缓解、严重事件和网络安全。条号和日期按当前合并文本核验。
6. 开源/开放权重只影响特定例外，不是全面豁免；系统层、Art.5和第三层法律仍需评估。

## 六、Layer 3数据和相邻法触发矩阵

### GDPR

每个目的单独判断Art.6，特殊类别数据再判断Art.9；角色决定Art.26或Art.28文件。大规模特殊类别、系统性监测、画像或重大自动化决定触发DPIA筛查。Art.22只覆盖完全自动化且有法律或类似重大影响的决定，形式性人工点击不够。

### 跨境

先充分性决定，再Art.46机制和TIA；Art.49仅例外。把远程访问、备份、分包、再传输和密钥控制纳入数据流。缺任一机制或证据，状态至少conditional，launch_blocker按风险决定。

### CCPA/CPRA和美国敏感数据

按美国资料文件检查California业务门槛、PI/SPI、sale/share、service provider/contractor、消费者请求、GPC和儿童；再独立检查美国联邦敏感数据限制的国籍/居住者、受关注国家、受限交易、豁免和日期。未核验的规则只能写pending_verification。

### PLD

先产品范围，再缺陷、损害、因果关系三要件；更新、持续学习、网络安全和重大修改作为缺陷事实。AI Act违规不是自动责任结论。

### CDSM

把抓取、复制、训练、RAG、缓存、展示和输出传播拆开；合法访问和权利保留逐项取证。Art.3科研TDM和Art.4一般TDM不混用，robots.txt不是唯一法律标准。

### ePrivacy

仅在终端设备存储/读取信息时触发Art.5(3)分析；Cookie、SDK、像素、设备指纹、麦克风/摄像头权限和通信保密另查成员国转置法。不能用它替代GDPR跨境机制。

## 七、风险和上线映射

| 触发情况 | 默认风险 | 默认状态 |
|---|---|---|
| 确认Art.5禁止实践 | 红色 | 暂缓上线 |
| 高风险系统已上线但核心义务/评定缺失 | 红色 | 暂缓或有条件上线，取决于是否可在上线前补齐 |
| GPAI系统性风险事实未核实 | 红色 | 暂不能确认/暂缓 |
| 第三国传输无充分性、Art.46或补充措施证据 | 红色 | 有条件上线或暂缓 |
| 仅有建议性材料缺口、强制义务有证据 | 黄色 | 可上线并列良好实践 |
| 关键事实不确定但无已确认红线 | 橙色 | 暂不能确认或有条件上线 |

风险不是法律责任概率的精确统计。报告必须解释触发事实、法律锚点和剩余证据缺口。
